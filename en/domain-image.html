Field guide · Image and design

Image generation: from a brief to a set you can accept

You type one prompt and get four images. The first looks great. But the shop needs six matching shots from the same angle with a Chinese price tag; the poster needs a title area; the character has to look the same in the next image. The job is not “get one good image”; it is “deliver a usable set”. Write the spec before choosing the model.

For Anyone making product shots, posters, character sheets or campaign images You leave with An image spec, an acceptance sheet and a path from generation to upscaling Time 12 minutes to read; about half a day for a six-image set Last checked 25 Nov 2026

This is Specul’s decision framework for image production, not a ranking of models or tools. Resolution, licences and platform rules remain with the linked pages and original sources.

If you only have five minutes
  1. Write the use, ratio, resolution, text and consistency requirements first.
  2. One good image does not mean a set is deliverable.
  3. Upscaling adds pixels; it does not invent missing detail.

The full guide starts below. Use the tables for reference; you do not need to memorise them.

One concrete job

Take one concrete job: six 1:1 product images for a coffee machine, with a Chinese price tag, consistent colour and angle, and a replaceable background. Write those five lines before choosing generation, editing or compositing.

Write the use, size, text and acceptance criteria first. One attractive sample image does not equal a deliverable set.

1 · Write the image spec before the prompt

The same prompt applied to an e-commerce hero, a social cover, a print poster and a game sticker has different requirements. A hero needs a clear subject, clean background and fixed ratio; a cover needs a safe area for the title; print needs enough resolution and bleed; a sticker needs transparency and clean edges. Write the use and spec first to judge whether an image is usable.

The spec should include: use, aspect ratio, output pixels, print or screen, colour space, transparency, text content and position, brand colours and fonts, references, forbidden elements and approver. Put them in one table that generation, retouching, layout and review all read.

2 · Model choice: generate, edit, control, upscale

Image tools fall into at least five jobs: text-to-image, image editing/inpainting, structural control, upscaling/restoration, and cut-out/background removal. They may come from one provider or several; do not use a text-to-image model for every job. Generation creates, editing changes a region, control locks composition, upscaling reaches output size, and cut-out prepares delivery format.

Model choice also depends on access and licence: a cloud API saves operations but sends data outside; local weights stay controllable but cost VRAM, setup and tuning; subscription tools are easy but commercial terms and output rights need reading. Eliminate options that fail licence or data-residency requirements before comparing quality and cost.

Rule of thumb: if editing can solve it, do not regenerate; if control can lock it, do not reroll the prompt and hope.

3 · Control: composition, pose, style and region

The point of control is to keep uncertainty where it belongs. Lock composition with edge, depth or line control; lock pose with a skeleton; lock style with references, LoRA or a fixed model; change one object with a mask and inpainting. Stronger control leaves less creative room; that is a trade, not “more is better”.

Record seed, prompt, control strength and references together. A prompt alone cannot reproduce an image; a seed alone cannot explain why the composition worked. Treat a generation as an experiment: variables, inputs, outputs and judgment are all logged.

  • Lock ratio and composition first with edge/depth/line control; avoid crop-after-generation.
  • Lock the subject with pose, reference or mask; fix what must not change.
  • Adjust style last: fix model/LoRA/reference and record strength and seed.
  • Change one variable at a time; keep the previous version and parameters.

4 · Consistency: character, product and scene

The hard part of a set is not the first image but the tenth still looking like the same character, product and scene. Character consistency fixes face, hair, wardrobe, age and expression range. Product consistency fixes shape, proportions, material, logo position and lighting. Scene consistency fixes space, time, palette and lens language. “The same person” in a prompt is usually not enough.

A workable method: build a character/product sheet (front, side, back, details, palette), then use references, fixed seeds, the same model/LoRA, pose control and inpainting. Run every image through the same consistency checklist. After generation, retouch skin tone, lighting and edges; do not pretend the model gets everything right in one pass.

5 · Text and typography: where models show their seams

Image models still make frequent errors in text, especially Chinese, small type, long lines and brand fonts: missing strokes, wrong characters, duplication, uneven spacing and soft edges. Treating text as a layout step rather than generated content is usually safer: generate a text-free base, leave a safe area, then set real type in a design tool.

If the model must generate text, do at least three things: constrain length and language, inspect every character at 100%, and retouch the text region separately from the background. Before delivery, recheck spelling, punctuation, brand names, prices and legal lines; these errors matter more than visual flaws.

Rule of thumb: do not let an image model render brand names, prices or legal lines. Set them in real type and inspect at 100%.

6 · Upscaling and output: pixels can grow, detail cannot be invented

An upscaler can increase pixels but cannot make detail that was never captured true. It may add crisper texture, or guess hair, text and product edges wrong. Before print, separate “native resolution” from “upscaled resolution”: the first determines detail, the second only file size.

Output depends on use: screen in sRGB at pixel dimensions for 72–96 ppi; print at physical size, a 300 ppi reference, bleed and colour space; transparent stickers with alpha edges and premultiplication; game/web with file size and format. After upscaling, check edges, text, repeated texture and colour shift before deciding to regenerate at a higher native resolution.

Screen
Fix first: Pixel dimensions, sRGB, format
Common error: Print-sized image on a web page

Print
Fix first: Physical size, 300 ppi reference, bleed, CMYK
Common error: Pixels without physical size

Transparent sticker
Fix first: Alpha edges, premultiply, halos
Common error: White/black fringes, dirty alpha

Game/web
Fix first: File size, format, loading
Common error: Lossless giant image slows loading

7 · Rights: model, input, likeness, trademark, output

Image rights have at least four layers: model/service terms, training data and style sources, rights in input references, and permitted use of output. A commercial model licence does not make a reference image commercial; owning the output does not make the likeness, trademark, building or artwork in it free to use.

High-risk inputs need separate handling: real people, minors, public figures, client products, brand logos and copyrighted characters. They need consent, scope, duration and attribution; some platforms also require AI-generated labels. Keep generation logs, reference sources and edit records for platform review or takedown.

Rule of thumb: write four lines — model licence, reference licence, likeness/trademark permission, output use — before generating. If any line says “unknown”, do not ship commercially.

8 · Acceptance: five tables, not one “looks good”

Image acceptance separates prompt adherence, defect rate, consistency, text accuracy, brand/aesthetic fit, and time/cost. Collapsing them into one “looks good” score hides what causes rework. A moody image with a distorted logo does not pass because it is attractive.

Acceptance samples should come from real use: ten images of one character, five angles of one product, three sizes of one layout, one line of copy in Chinese and English. Use at least two reviewers, blind first and spec-check second. Keep failures and parameters so the next generation converges.

Prompt adherence
What to check: Subject, action, composition, exclusions
Failure example: Right subject, wrong composition

Defects
What to check: Fingers, edges, repetition, texture
Failure example: Product edge melts

Consistency
What to check: Character/product/scene across images
Failure example: Face changes by image ten

Text
What to check: Spelling, font, position, legibility
Failure example: Missing strokes, wrong price

Brand/aesthetic
What to check: Palette, style, platform fit
Failure example: Looks like a competitor or off-brand

Time/cost
What to check: Time and calls per accepted image
Failure example: Twenty retries for one image

9 · Failure branches: locate the error before regenerating or editing

Not every failure needs regeneration. If composition and subject are right and one region is wrong, inpaint first. If composition or subject is wrong, regenerate. If text is wrong, go back to layout. If resolution is short, decide whether native detail or upscaling is the issue. Change one variable and keep parameters.

Extra fingers, limbs
Fix first: Inpaint/pose control
Check: Inspect edges at 100%

Garbled text
Fix first: Regenerate without text + layout
Check: Character-by-character, real font

Style drift
Fix first: Fix model/LoRA/reference
Check: Compare with style board

Identity drift
Fix first: Character sheet + reference + inpaint
Check: Blind-test ten side by side

Composition ignored
Fix first: Edge/depth/line control
Check: Check control map and strength

Upscale looks worse
Fix first: Regenerate at native resolution
Check: Compare native and upscale at 100%

Commercial rejection
Fix first: Check the rights table
Check: Model, reference, likeness, trademark

Decide whether it can be edited before deciding to regenerate. Regeneration is the most expensive fix.

10 · A minimum path to a deliverable image set

Make one hero image and one hardest variant first, not twenty images at once. The hero validates spec and style; the variant validates consistency and text. Expand only after both pass.

  • Write the spec table: use, ratio, pixels, text, colour, references, exclusions, approver.
  • Make one hero: validate subject, composition, style and output size.
  • Make the hardest variant: new angle, scene or text; check consistency.
  • Lock control: fixed seed, model/LoRA, references and masks; record strength.
  • Set text later: generate a text-free base, leave a safe area, use real type.
  • Upscale and export by use: screen sRGB, print CMYK/bleed, transparent alpha.
  • Run consistency acceptance: ten side by side, blind, checked against spec.
  • Build the rights table: model, reference, likeness, trademark, output use.
  • Keep parameters and failures; start the next generation from records, not memory.
Done means the spec matches, ten images stay consistent, text is legible, output is usable and rights are traceable — not merely that a few images look good.
